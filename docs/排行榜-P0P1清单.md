# 排行榜 P0 + P1 实施清单

> 用途：照着做即可。每条都写了**改哪个文件的哪一段**、**为什么**、**怎么验收**。
> P0 不动网络、随时可停；P1 只有一项会触碰线上（部署一次测试包）。
> 状态标记：`[ ]` 未做 · `[x]` 已做 · `[!]` 卡住（把现象写在该条下面）

## 0. 前提（先读，省得白干）

| 事实 | 影响 |
|---|---|
| 线上是 GitHub Pages 静态托管 | 全服榜必须有外部后端，本机榜不需要 |
| `ScoreBoard` 已经在按昵称存 best | P0 是**增量**，不是重写；老存档必须能读 |
| 云 SDK 是 JS（PostgREST 封装），GDScript 调不到 | 必须经 `JavaScriptBridge` ↔ `web/shell.html` 中转 |
| 桌面 exe 没有 JS 桥 | 全服榜只在 web 版；桌面降级读缓存，不报错 |
| 分数由客户端算 | 拦得住自相矛盾，拦不住有心人——别在这上面追求"安全" |
| `scripts/zone.gd` 正被另一个会话改（5:04 版） | 本清单**不碰** zone.gd；`zone_cap` 只出现在 P1 的表结构里，用来挡住旧版本分数 |

## 1. P0 · 本机榜（无网络依赖）

目标：菜单里能看到**最近打过的每一局**，结算时知道自己是本机第几名。
现在只有"每个人一条最高记录"，破不了纪录的局等于没发生过。

### P0-1 存档升到 version 3

- [ ] 文件：`scripts/score_board.gd`
- 改：`const VERSION: int = 3`；新增 `const MAX_RECENT: int = 20`
- 每个 player 增加 `recent` 数组，元素形如
  `{score, kills, elite_kills, level, xp_total, elapsed, hero, cleared, date}`
- `submit()` 里**无论是否破纪录**都往 `recent` 头部插一条，`resize(MAX_RECENT)` 截断
- `_read()` 返回前做一次归一：`recent` 不是数组就补 `[]`（老档天然升级，不用写迁移分支）
- 新增 `_normalize_run(raw) -> Dictionary`，照 `_normalize_best` 的写法把 JSON 的 float 转回 int

**为什么不用写迁移代码**：JSON 里缺的 key 读出来就是 `null`，`_read` 已经是"缺什么补什么"的风格，
把 `recent` 当成又一个可选字段即可。`version` 只是给以后的人看的。

验收：
- 现有 `user://records.json`（version 2）打开不报错、best 不变
- 打一局 → `recent` 多 1 条；打破纪录时 best 和 recent **都**更新
- 连打 25 局 → `recent` 长度停在 20，最旧的被挤掉

### P0-2 新增"最近对局"查询

- [ ] 文件：`scripts/score_board.gd`
- 新增 `static func recent_runs(limit: int = 20) -> Array[Dictionary]`
- 把所有玩家的 `recent` 合起来，每条补上 `name`，按 `score` 降序，取前 `limit`

**为什么要合并所有玩家**：菜单右列只有 252px 宽，没有地方再放一个"选择玩家"。
"本机最近 20 局"对所有玩家都有意义（换人玩时能看到上一位的成绩）。

### P0-3 结算时把 hero 记进存档

- [ ] 文件：`scripts/game.gd`（`_on_player_died()` 里 `ScoreBoard.submit(...)` 那一段，约 1380 行）
- 提交的字典加两个字段：`"hero": _hero`、`"cleared": _cleared`（`cleared` 现在已传，保留）
- 返回值多带两个键：`"local_rank"`、`"local_total"`

```gdscript
var board: Array[Dictionary] = ScoreBoard.list_players()   # submit 之后调用，best 已更新
var local_rank := 1
for i in range(board.size()):
    if str(board[i]["name"]) == str(_profile["name"]):
        local_rank = i + 1
        break
result["local_rank"] = local_rank
result["local_total"] = board.size()
```

注意顺序：**先 `submit`，再 `list_players`**，否则读到的是上一局的排名。
这段循环放在 `var result: Dictionary = breakdown.duplicate()` 之后、`hud.show_game_over(result)` 之前。

### P0-4 菜单右列加"本机 / 最近"切换

- [ ] 文件：`scripts/ui/start_menu.gd`
- `_build_columns()` 右列：把现在那句 `UiKit.label("本机战绩", ...)` 换成两个小按钮（tab）
- 新增成员 `var _tab: int = 0` 和 `var _players: Array[Dictionary] = []`
- `open()` 里把传入的 `players` 存进 `_players`，再 `_refresh()`
- `_refresh()` 按 `_tab` 取数据：0 → `list_players()`，1 → `ScoreBoard.recent_runs(MAX_ROWS)`
- 两个 tab 的按钮样式复用 `_make_class_button` 的写法（选中态换边框色），不要新建一套配色

**踩过的坑**：卡片/按钮的**图标底板 `PanelContainer` 默认 `MOUSE_FILTER_STOP`，会把点击吃掉**
（触屏尤其明显）。新加的 tab 按钮如果内部有 Panel，必须设 `MOUSE_FILTER_IGNORE`。

`_make_row()` 需要分支：`最近` 模式下第 3 列显示「分数」、第 4 列显示「时长 + 日期」，
日期的完整文本塞 `button.tooltip_text`（252px 放不下）。

验收：
- 桌面点两个 tab 都能切，切完不丢当前昵称
- 手机（844×390 触摸模拟）点 tab 有反应 —— 这条必须真点，`_gui_input` 在这套 UI 里不可靠
- 空档时仍显示"还没有任何记录，你将是第一个。"

### P0-5 结算面板加本机名次

- 第 1 名用金色 `Color(1.0, 0.85, 0.45)`，其余用 `Color(0.72, 0.79, 0.9)`
- 字号 14，`horizontal_alignment = CENTER`，与上下行保持同一节奏

**不要写"全服第 N"**：P0 没有网络，写了就是假数据，后面接真榜时还得改文案。

### P0-6 自检

- [ ] 新增 `dev/board_check.gd`（照 `dev/zone_probe.gd` 的结构：静态断言 + 末尾打印 `N 通过 / M 失败`）
- 覆盖点：
  1. 空档 → `recent_runs()` 返回空数组，不崩
  2. 写 3 条不同分数 → 排序正确
  3. 写 25 条 → 长度 20，且保留的是最新的 20
  4. version 2 的老档（手写一个 fixture 塞进 `user://`）→ 读出来 best 不变、recent 为空数组
  5. `local_rank` 在并列分数时的行为（现在按昵称字典序，**先明确预期再断言**）

## 2. P1 · 全服连通性（只验能不能通，不做 UI）

目标：在**真实域名**上确认"能连、能写、能读"。这一步不通，后面的 UI 全部作废，
所以先花最小的代价把它撞出来。

### P1-1 开通云服务

- [ ] 在云服务面板里为这个应用激活环境（**这步必须你自己点确认**，我不能代按）
- 记下 `publicConfig` 三个值：`endpoint`、`publishableKey`、`oauthRelayBaseUrl`
- `publishableKey` 可以出现在前端源码里（服务端按 Origin 校验），但**别写进日志**

### P1-2 建表 + 校验（一次定死）

- [ ] 执行下面这段 SQL（`create table` 的动作在管理端做，不要写进游戏代码）

```sql
-- 分数公式的服务端副本。必须与 scripts/score.gd 的常量逐个对齐。
create or replace function public.lb_expected_score(
        kills int, elite_kills int, elapsed real, level int, xp_total int, cleared boolean)
returns int language sql immutable as $$
  select greatest(kills - elite_kills, 0) * 10
       + elite_kills * 45
       + floor(elapsed)::int * 8
       + greatest(level - 1, 0) * 120
       + greatest(xp_total, 0) * 2
       + case when cleared then 2500 else 0 end;
$$;

create table if not exists public.leaderboard (
  id          bigserial primary key,
  name        text        not null check (char_length(name) between 1 and 12),
  score       integer     not null check (score > 0),
  kills       integer     not null check (kills >= 0),
  elite_kills integer     not null check (elite_kills >= 0 and elite_kills <= kills),
  level       smallint    not null check (level between 1 and 80),
  xp_total    integer     not null check (xp_total >= 0),
  elapsed     real        not null check (elapsed > 0 and elapsed <= 500),
  cleared     boolean     not null default false,
  hero        smallint    not null check (hero between 0 and 2),
  zone_cap    smallint    not null check (zone_cap in (304, 480)),
  build       text        not null check (char_length(build) <= 24),
  created_at  timestamptz not null default now(),
  constraint kill_rate check (kills <= elapsed * 40)
);

create index if not exists leaderboard_score_idx
  on public.leaderboard (score desc, created_at asc);

alter table public.leaderboard enable row level security;
create policy lb_read   on public.leaderboard for select using (true);
create policy lb_insert on public.leaderboard for insert
  with check (score = public.lb_expected_score(kills, elite_kills, elapsed, level, xp_total, cleared));
-- 故意不给 update / delete：写进去就改不了
```

三条设计意图，别顺手改掉：

1. **`score` 用函数复算**，不是"看着像就行"。公式是 `Score.gd` 的副本，改公式时**两边都要改**，
   所以 P1 结束前用 3 组固定向量（如 kills=100/elite=5/elapsed=300/level=20/xp=20000）
   同时喂给 GDScript 和 SQL，两边结果必须相等。只改一边，线上会**全员提交失败**。
2. **`zone_cap` 是白名单，不是写死的上限**。时间轴每改一版就在这里加一个值；
   现在表里是 `304`（5:04 版，另一个会话在做）和 `480`（线上 8:00 版）。
   **宁可拒掉新版本的分数，也不要让"任意值通过"**——这就是上次 `bot.gd` 把 690 写死、
   改表后断言永远报 0 的那个坑的反面。
3. **`kills <= elapsed * 40`**：实测射手峰值约 23 杀/秒，留 1.7 倍余量。这条能挡掉九成手改数据。

### P1-3 在 shell 里接 SDK + 一个最小桥

- [ ] 文件：`web/shell.html`
- 在 `$GODOT_URL` 那个 `<script>` **之后**加 CDN（`export_presets.cfg` 里 `custom_html_shell`
  指向它，导出时会内联进 `index.html`，**不需要改 `deploy_pages.sh` 的白名单**）：

```html
<script src="https://cdn.jsdelivr.net/npm/@tencent-ai/workbuddy-cloud-sdk@dev/lib/index.global.js"></script>
```

- [ ] 在已有的那个大 `<script>` 里（`window.__nsState` 附近）加桥。写法沿用你现有的
  **"JS 写状态、GDScript 轮询"** 模式，**不要**用 `JavaScriptBridge.create_callback` 接 Promise：

```js
window.__nsLbState = JSON.stringify({ phase: 'idle', rows: [], error: '' });
let nsCloud = null;
function nsLbInit() {
  if (nsCloud) return nsCloud;
  if (typeof WorkBuddyCloud === 'undefined') throw new Error('sdk_missing');
  nsCloud = WorkBuddyCloud.createWorkBuddyCloud({
    endpoint: '<ENDPOINT>',
    publishableKey: '<PUBLISHABLE_KEY>',
  });
  return nsCloud;
}
function nsLbSet(o) { window.__nsLbState = JSON.stringify(o); }

window.__nsLbTop = function (n) {
  nsLbSet({ phase: 'loading', rows: [], error: '' });
  const timer = setTimeout(function () {
    nsLbSet({ phase: 'error', rows: [], error: 'timeout' });
  }, 3000);
  try {
    nsLbInit().database.from('leaderboard')
      .select('name,score,kills,elapsed,hero,created_at')
      .order('score', { ascending: false }).limit(n)
      .then(function (r) {
        clearTimeout(timer);
        if (r.error) { nsLbSet({ phase: 'error', rows: [], error: String(r.error.message || r.error) }); }
        else { nsLbSet({ phase: 'ok', rows: r.data || [], error: '' }); }
      })
      .catch(function (e) { clearTimeout(timer); nsLbSet({ phase: 'error', rows: [], error: String(e) }); });
  } catch (e) {
    clearTimeout(timer);
    nsLbSet({ phase: 'error', rows: [], error: String(e) });
  }
};
```

- 这段代码**先只做读**。写（insert）等读到数据再补，一次只验一个方向。

**CDN 可能拉不到**（jsdelivr 在部分网络下很慢或被拦）。现象是 `error: "sdk_missing"`。
兜底：把 `index.global.js` 下载到 `web/`，在 `deploy_pages.sh` 第 34 行的 `FILES=(...)`
里加一个文件名，并改成 `<script src="index.global.js">`。这时**必须**改白名单，
否则线上 404（白名单只发 10 个文件，别以为它会自动带上）。

## 4. 回滚

- P0 全部是本地文件，`git revert` 即可；存档 version 只升不降，回滚后旧代码会把 `recent` 忽略掉，**数据不丢**
- P1 线上回滚：`./deploy_pages.sh --no-export` 重推上一个 gh-pages 提交
- 表一旦建好别删（删了要重建 RLS 和索引）；脏数据用 `delete from leaderboard where build = '...'` 精确清

## 5. 已知坑（按踩到的顺序）

1. **图标底板吃点击**：`PanelContainer` 默认 `MOUSE_FILTER_STOP`，桌面同样有这 bug，不是手机专属。
2. **`--check-only` 必跑**：多行缩进块改完不检查，`for` 循环体会被顶出去，报 `Identifier not declared`。
3. **自检写真实存档**：`dev/*.gd` 直接读写 `user://`，跑之前先备份。
4. **无头窗口默认 64×64**：任何涉及尺寸的断言先 `get_window().size = Vector2(1280, 720)`。
5. **CDN 忘了改白名单**：本地托管 SDK 时最容易漏，线上表现为 404 + `sdk_missing`。
