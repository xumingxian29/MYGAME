# 暗夜幸存者

一个用 **Godot 4.7.2** 写的 Vampire Survivors 类自动战斗生存游戏。桌面和手机浏览器都能直接玩。

**在线试玩：<https://xumingxian29.github.io/MYGAME/>**

---

## 玩法

存活越久分数越高。角色自动攻击，你只需要走位；升级时三选一加强属性；蓝条满了放一次主动技能。

**目标不是活得久，是走出城堡**：穿过十道门、在王座厅连败五位守门人，从西城门走出去。
没走出去的一律按死亡结算——奖励只发给逃出去的人。

**而且门外不止一种样子**：十道门你分别怎么选，决定了最终走到五个结局里的哪一个。

**地图是一间间迷宫房**：每张图程序化生成 9 个房间 + 走廊，墙是实心的，绕不进去。
其中一间是**商人密室**——走进去就能用金币买药。打完整张图的 Boss 会在原地开**四扇传送门**
（单卡 / 双卡 / 破甲弹 +3 / 金币 +90），**踩上去不会直接走**，面板里点「继续前进」才传。

**一局最多走十道门，第十道门之后不再有迷宫**。走过十道门就进**王座厅**：一片没有墙的空场，
上一章的老面孔一位接一位从影子里站起来，连打 **5 位守门人**，中间只隔 2.4 秒。
五位全倒下之后，场上只开**一扇金色的门**——踩上去是这局唯一的结局：**走出城堡**。

**四扇门给的是"下一幕的相对难度"，不是永久累加的涨幅**：

| 门 | 奖励 | 下一幕 |
|---|---|---|
| 单卡 | 1 张升级卡 | **×0.95** |
| 破甲弹 | +3 发 | **×1.05** |
| 金币 | +90 | **×1.10** |
| 双卡 | 2 张升级卡 | **×1.15** |

难度 = **这一幕的基准**（`Stage.POWER`，1.00 → 2.10，只跟"走到第几幕"有关）
× **上一扇门的偏移**。偏移只作用于下一幕、**不累积**：一路选双卡平均 1.15×，
一路选单卡 0.95×，相对差 20%——肉疼，但不至于判死刑。

旧版是"每门 +20%~+100% 加法累加"，那是给 3~5 层的无尽局定的；搬到十幕后
第十幕要累到 +900%，而玩家每个属性有 3 倍硬封顶（`StatCurve.CAP`）。
敌人涨 11 倍、玩家封顶 3 倍，台架 10 局 0 次逃出、中位 201 秒——那条路走不通。

**墙是真的墙**：玩家、小怪、Boss 都不会生成在墙里，也无法走进墙里；攻击同样不能穿墙——
子弹撞墙即灭，近战和回旋镖在命中前要做视线采样。隔着墙角偷输出不可行。

**每张图的敌人属性按难度系数放大**，没有时间上限——死了才结算。

**升级只给卡，不回血；传送也不回血**。血只有四个来源：脱战自然回复、Boss 战后 15%、
通关补满、商人。所以「这一波要不要绕回商人那儿」是一个真的要权衡的决定。

**视野里同时最多 40 只怪**（Boss 战仍是 10 只）。超出的会被推回屏幕外等着，
而不是原地蒸发——屏外仍然排队，但画面里的压力是恒定的。
上限从 20 提到 40 是为了让后期的「清场感」真的成立：40 只怪铺满屏幕的时候，
清掉一片的反馈是看得见的，而不是屏幕上永远只剩五只。

### 一局的结构：十道门，每章三分钟

一章 = 迷宫刷怪 + 关底 Boss + 挑门，**总时长按 180 秒配**（三分钟）。所以刷怪段是
**递减**的 142 / 134 / 124 秒——不是越往后越短，而是关底越硬（18/23/28 发），
留给小怪的时间必须相应变短。十幕走完约 30 分钟，加王座厅约 32 分钟。
`breach_check` 里有一条按表算的断言（每章 165~200s、整局 25~35 分）钉住这件事。

### 五个结局：门是怎么选的，门外就是什么

每道门四种奖励，也就是四种"这条路"：

| 门 | 拿到什么 | 代价 | 记账时叫 |
|---|---|---|---|
| 单卡 | 1 张升级卡 | 下一幕 ×0.95 | **稳** |
| 破甲弹 | +3 发 | ×1.05 | **战** |
| 金币 | +90 | ×1.10 | **财** |
| 双卡 | 2 张升级卡 | ×1.15 | **贪** |

十道门走完，票数最多的那一类决定门外：

| 结局 | 触发 | 门外 |
|---|---|---|
| **黎明** | 单卡最多 | 你只是走了出去，什么都没多带 |
| **新的王** | 双卡最多 | 城堡换了一个囚徒——它在笑 |
| **烧掉的路** | 破甲弹最多 | 你不是推开门，是把门打穿的 |
| **买下的门** | 金币最多 | 锁是金子敲开的，没人记得走出来的那个人 |
| **杂色的清晨** | 没有主导（最高票 ≤3，如 3/3/2/2） | 每样只拿一点，身上没有一样东西是纯粹的 |

- 票数并列时**由最后一次选择破平**——"我最后想要的是这个"比"表里它排在前面"更像玩家的意愿
- 结算面板写着「结局 2/5 · 新的王」，并记进本地存档的**结局图鉴**（「已解锁 3/5 个结局」）
- 选门确认面板底部有一行「走过的路：稳 2 · 贪 4 · 战 1 · 财 1」（含正在选的这一扇），
  所以这个机制在**游玩过程中**就是可见的，不是结算时才揭晓
- 王座厅那道金门下面写的也是你这个结局的门外名，不是固定的"黎明"

### 王子的十幕

这一局有一个故事，而且它不留白：开场、每一次穿门、五位守门人出场、死亡结算、胜利结算，
说的都是同一件事——**王子在往外走，城堡在往回拉**。

十幕各有名字（铁门之后 / 无人的长廊 / 熄灯的宴会厅 / 渗水的回廊 / 镜厅 /
塔基的螺旋 / 无光的礼拜堂 / 灰色的雪 / 九级台阶 / 王座之前），各有配色：
冷蓝的地牢、暖橙的宴席、紫色的镜厅、血红的王座。**不看字也能从颜色上知道"更深了"**。

- **开场和每次穿门后各播一段**，逐字显示，点一下补完当前行、再点进下一行
- **右上角永远有一颗「跳过」**：十次剧情，第二次玩家就会开始找怎么过快点。
  跳过是一次点击直接到底，不是"跳到下一行"
- 台词在 `scripts/story.gd` 里集中管，一句一行、每行不超过 24 个汉字（手机横屏的上限）
- 五个结局各有一套三行收尾，写在同一个文件里（`ENDINGS`），调文字不用翻代码

### 升级与属性上限

每张卡给的数值**不是**直接乘上去的，而是先累加成一个「原始值」，再走一条饱和曲线：

```
最终倍率 = 1 + (3 - 1) × raw / (raw + (3 - 1))
```

于是第一张攻击卡大约 +19.8%（几乎没折扣），第十张只剩几个点，四十张卡合计 **2.63 倍**——
**永远到不了 3 倍，3 倍是天花板而不是目标**。这就是「前面提升多、后面提升少」：
它让前五个升级的每一下都摸得到，又让后期不会因为卡多而变成滚雪球。

曲线只作用于**数值类**（伤害、攻速、移速、血量、拾取范围……）。计数类（额外弹道、
穿透 +1、环绕飞刃 +1）不受曲线约束，因为「多一发子弹」这件事没法打折。

### 三个职业

| 职业 | 定位 | 血量 | 主动技能 |
|---|---|---|---|
| 战士 | 近战 · 高血 | 180 | **旋风斩**：1.2 秒无敌，劈开并击退周围敌人 |
| 法师 | 远程 · 高伤 | 100 | **奥术新星**：大范围爆伤，命中者减速 2.5 秒 |
| 射手 | 远程 · 高射速 | 110 | **箭雨**：向四周射出 14 支穿透箭矢 |

### 三个难度档位

主菜单三选一，**默认「轻松」**（11/28 拍板：新玩家第一次进来先让他赢），选过的档会记住，
下次开局还是它。三档共用同一条难度曲线，只叠乘数——没有三套数值表：

| 档位 | 玩家受击 | 每幕开头 | Boss 战 | 每波数量 |
|---|---|---|---|---|
| 轻松 | **×0.75** | 回 15% 最大生命 | 补 2 发破甲弹 | 不变 |
| 标准 | ×1.00 | — | — | 不变 |
| 硬核 | **×1.10** | — | — | **×1.20** |

轻松档**刻意不减怪**：减怪会减经验，玩家升级变慢、DPS 更低——那是死亡螺旋
（P0 实测过），不是难度台阶。四个旋钮全部不碰经济。

台架（seed 11–15，bot 走默认轻松档）：通关 **5/10**、中位存活 **1611.6s**；
标准档对照：通关 3/10、中位 1397.4s。两条数据都比重排前的 0/10 / 201s 走得远。

### 操作

| | 桌面 | 手机（横屏） |
|---|---|---|
| 移动 | `WASD` / 方向键 | 左下虚拟摇杆（推一半就是半速） |
| 技能 | `空格` | 右下技能键（蓝条满时变金色） |
| 暂停 / 继续 | `P` / `ESC` | 右上「暂停」键（暂停后变成「继续」） |
| 返回主菜单 | 先按 `P`/`ESC`，再点面板里的「返回主菜单」 | 先点「暂停」，再点面板里的「返回主菜单」 |
| 升级选卡 | 点卡片 或 `1` `2` `3` | 点卡片 |
| 剧情 | 点一下 / `空格` 推进，`P` 或点右上「跳过」跳整段 | 点屏幕推进，点右上「跳过」 |
| 死亡后 | `R` 再来一局 · `P` 换人 | 点按钮 |
| 胜利后 | `R` 再来一局 · `P` 换人 | 点按钮 |

### 金币与商人

击杀掉金币：普通怪 6、特殊怪（冲锋 / 吐息 / 自爆）9、精英 24、Boss 120，
并且**每深入一张图 +30%**。**金币跨图保留**，换图不清零。

每张图的商人密室里摆三件货，走近自动开面板，每件每图限购一次：

| 商品 | 基础价 | 说明 |
|---|---|---|
| 治疗药剂 | 1600 | 前三图回复 **5%** 最大生命，第 4 图起固定 **100 点**。这一排里最贵的一件 |
| 破甲弹 ×3 | 600 | 装到武器上：下一次攻击自动变成穿甲弹。最便宜——不该让玩家因为穷而卡关 |
| 战术手册 | 1200 | 立刻一张升级卡 |

**价格每深入一张图 +45%**（`基础价 × (1 + 0.45 × 图数)`）。涨幅比金币的 +30% 快，
所以「越深越贵」是真的有负担，而不是数字变大、购买力不变。
第 6 张图的药剂要 5200，那时候一瓶 100 点血要不要买，是个决定。

### 关底 Boss

每章走完出一个关底，一场 25~45 秒。Boss 身上有壳：**普通武器和技能打不进去**
（打在壳上是一记冷色闪光，血条不动）。

**破甲弹是开火即消耗**：手上有一发，下一次攻击就会变成穿甲弹——子弹、近战挥砍、
回旋镖投掷都行。命中必有效果，不再是「打早了白扔」：

- **打在破甲窗口里** → 40 点满额伤害，并且**把窗口续 0.6 秒**。手上有弹、打得够准，
  就可以把一只 Boss 的窗口无限续住。
- **打在窗口外** → 只有半额 20 点，但会**直接把 Boss 打进破甲**。这是「主动开窗」，
  代价是你多花了半发。

**Boss 血条贴屏幕最顶部整宽一条**（名字 + 血条 + 阶段 + 状态字），左右两栏永远为它让位，
所以开战时 HUD 不会跳一下。

| 阶段 | 时长 | Boss | 你要做的 |
|---|---|---|---|
| 连招 | 4~6 秒 | 定身 · 无敌 · 连续出招 | 读前摇、躲。新招式「裂地」会在地上连开 5 处，落点跟着你的跑向预判 |
| **破甲** | **3.0 秒**（可被续） | 定身 · 可被破甲弹打伤，血条与本体转金色，屏幕中央提示音 | 贴上去把弹打空 |
| 追击 | ≤2.4 秒 | 走向你 | 拉开距离，准备下一轮 |

血条右侧常驻一行状态字（`攻击中 · 无敌` / `破甲 2.4s`），不用去找。
前三场关底合计要 **69 发**破甲弹（每发 40 点满额算），弹只在这三场里掉（约 1.4~1.6 秒一枚），
所以打得动打不动取决于你在窗口里捡没捡、打没打，和卡片强度无关。

### 王座厅：五位守门人

走过第十道门就没有迷宫了。王座厅是一片空场，**进场先补 4 发破甲弹**——
这不是怜悯，是保底：一路走过来没捡到弹的人，在这里会被壳活活耗死，那不是难度，是死局。

守门人一位接一位上，中间 2.4 秒喘气，破甲窗口比外面密（每 1.5 秒开一次）：

| # | 守门人 | 血量（发） | 它是谁 |
|---|---|---|---|
| 1 | 潮主 | 12 | 宴会厅桌下那只，又被推了上来 |
| 2 | 蚀影 | 14 | 镜子碎了，它还在 |
| 3 | 深潜者 | 16 | 它从来没浮上过水面 |
| 4 | 暗影王子 | 18 | 那是你——先一步走到了这里 |
| 5 | 无光之王 | 20 | 王座是空的，空着的地方站起来了 |

合计 80 发。**五位全倒 → 场上只开一扇金色的门**，门下面写着你这个结局的门外名
（「西门外 · 黎明」/「西门外 · 新的王」……）。
踩上去就是胜利结算：逃离 **+8000 分**，记一次「第 N 次逃出城堡」和一个结局图鉴条目到本地存档。
死亡结算里不再有「三章通关」这一项，通关奖励被胜利取代——**只有走出去算赢**。

## 本地运行

需要 Godot 4.7.2。

```bash
# 编辑器里跑
godot --path .

# 直接跑
godot --path . MY主场景.tscn
```

没有触摸屏的电脑也想试摇杆，加 `-- --touch` 强制开触屏模式（此时用鼠标拖就是手指）。

## 导出 Web 并发布

```bash
./deploy_pages.sh            # 导出 + 推送到 gh-pages 分支
./deploy_pages.sh --no-export   # 只重推现有 build/web
```

脚本会把 `build/web` 里的产物打进一份**只有单个提交**的临时仓库强制推送，
所以 40MB 的 wasm 不会在分支历史里逐次堆叠。

本地预览（不要用 `file://` 直接打开，必须走 HTTP）：

```bash
python serve.py 8080          # http://127.0.0.1:8080/
python serve.py 8080 --lan    # 同一 Wi-Fi 的手机也能打开
```

### 右上角：小地图

24×18 格按 **1 格 5 像素**烤成 120×90，右侧留边对齐分数和暂停键。

- 白点是你，红点是**560 像素内**的敌人，金菱形是商人，青色方点是开着的门，橙圈是 Boss
- **墙和地板只在换图时烤一次**（432 格），每帧只画十来个点——地图在一幕里根本不变，
  每帧重画 432 个 `draw_rect` 是纯浪费
- **只画雷达范围内的敌人，不做全图透视**。小地图的用处是"我在这张图的哪一头、
  商人往哪边走"，不是隔墙看怪；全图点亮会把"绕回来撞见一群"变成"提前知道"，
  那是改玩法，不是加辅助
- 5 像素是**整数倍下限**：最窄的走廊只有 1 格宽，再小就只剩一条半透明的线，
  地图会变成噪点

## 兼容性

- 渲染后端固定 **GL Compatibility**（Web 唯一可用的后端）
- 用 **nothreads** 模板导出，不依赖 `SharedArrayBuffer`，所以 GitHub Pages 这类无法下发
  `Cross-Origin-Opener-Policy` 的静态托管也能直接跑
- 字体内嵌 `Noto Sans SC` 子集（Web 上 `SystemFont` 会静默退化，必须内嵌）
- 存档存在浏览器 IndexedDB 的 `/userfs` 下，换设备不同步
