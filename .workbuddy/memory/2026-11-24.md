## 第四轮：降前期难度 + 计分系统

### 评分（`scripts/score.gd`，43 行）
权重常量集中在一处：普通小怪 10 分/只、精英 45 分/只、存活 8 分/秒、每级 120 分、每点累计经验 2 分。
`Score.compute()` 返回拆解字典（结算面板逐行展示），`Score.total()` 只返回总分（HUD 每帧调用，避免每帧构造字典）。

### 最高分存档（`scripts/score_board.gd`，48 行）
`user://records.cfg`（实际路径 `%APPDATA%/Godot/app_userdata/MY GAME/records.cfg`），`ConfigFile` 存 `[best]`（score/kills/elite_kills/level/xp_total/elapsed/date）+ `[stats]`（runs、total_kills）。
`ScoreBoard.submit(run)` 返回 `{best, is_best, runs}`；只有破纪录时才覆盖 best，所以低分局不会把纪录冲掉（已验证连续 7 次重开 best 不变）。

### HUD
- 右上角常驻「分数 N / 最高 N」，`set_score(current, best)` 每帧刷新。
- 结算面板改成多行拆解：击杀/存活/成长三行 + 总分 + 历史最高（破纪录金色「新纪录！」）+ 第 N 次挑战 + 距最高差。
- 升级面板与结算面板复用同一个居中 PanelContainer，切场景时用 `_clear_panel()` 重建并换边框色（蓝=升级、红=结束）。

### 难度改动（这才是重点）
前期变简单的关键不是调单个数值，而是**加了场上敌人上限**：`_enemy_budget() = 12 + 存活秒数/3`，到顶就停止刷怪。
之前没有闸门，刷怪每秒数只、单目标子弹每秒清不到 1 只，屏外会堆到 300+ 只，血量掉得莫名其妙。
- 难度压力 `_pressure() = clamp((t-45)/150, 0, 1)`，刷怪间隔 `lerp(0.7, 0.28, pressure)`，每 35 秒每波 +1 只。
- 敌人 HP `8 + 0.2t`（原 `12 + 0.85t`，涨太快，玩家输出根本追不上）；速度 62–94，成长 +0.35/s 上限 +46。
- 精英：45 秒起 12% 概率，HP ×3.2、速度只 ×0.85（原来 ×0.72，太慢会永远落在队伍后面，杀不掉）。
- 接触伤害 6/12、敌人触碰冷却 1.0s；玩家 120 血、无敌帧 0.45s；子弹 14 伤 / 0.5s。
- 经验：普通 2、精英 6；升级需求 `×1.22+1`；宝石磁吸 360（射程 420），另外**掉在 700 以外的宝石会按距离加速飘回来**。

### 实测（headless + bot）
- 站立不动：37s（最初）→ 45s（只调数值）→ **77s**（加预算 + 磁吸后），结束时 Lv.13 / 168 杀。
- 会走位的 bot：300s 前不死，340s 时 Lv.13 / 278 杀；调之前 340s 只有 Lv.6 / 173 杀且场上堆 125 只。
- 关键教训：**不要把"难度"只当数值问题**。刷怪与清怪速率失衡时，越调敌人越弱，屏幕上敌人越多，玩家反而更快被围死。

### 探针踩坑
- `args.has("--die-at")` 对 `--die-at=15` 是 false（精确匹配），用 `_arg(args, key, -1.0) >= 0` 判断存在性。
- `--quit-after` 单位是帧：`--die-at=40` 配 `--quit-after 1800`（30 秒）会来不及死就退出，什么都没打印。

## 第五轮：代码通读评审（无改动，只出结论）

游戏类型判定：Vampire Survivors 式自动射击 roguelite（bullet heaven）。

确认存在的缺陷（按严重度）：
1. **刷怪点在视野内**。默认视口 1152×648、`Camera2D.zoom = 1.35` → 世界视野 853×480，半宽 426.7 / 半高 240。
   `_spawn_enemy()` 用 `randf_range(340, 430)`，水平方向 340~426 全在屏内 → 左右边缘会看到怪突然出现；开局 6 秒的 `randf_range(260, 350)` 四个方向都可见。
   正解：按视野尺寸算外接半径（`get_viewport_rect().size / CAMERA_ZOOM` 的对角线的一半再加一点余量），而不是写死常量。
2. **敌人无分离**，全体收敛到玩家同一坐标，视觉上叠成一个点。`_drift` 只是常量侧偏，不能代替 separation。
3. `_probe()` 在 `_physics_process` 里无条件执行，每帧调 `OS.get_cmdline_user_args()` 分配 PackedStringArray；且 200 行探针代码混在生产脚本里。
4. `Enemy._flash()` / `Player._flash()` 每次受击 `create_tween()`；高密度下每秒新建销毁近千个 Tween，且多次受击的 Tween 会互抢 modulate。
5. 无 InputMap，`player.gd` 硬编码 `Input.is_key_pressed(KEY_A)`，无法改键、无手柄。
6. 全代码建场景，无 `player.tscn` / `enemy.tscn` / `gem.tscn`，`PackedScene` 预载为零 → 加美术资源时无处挂 Sprite2D/AnimationPlayer/粒子。
7. 工程卫生：`my主场景.gd` 是孤儿（真实主场景脚本是 `scripts/game.gd`）；`res://MY主场景.tscn` 中文资源名；`project.godot` 里 `3d/physics_engine="Jolt Physics"` 是模板残留；无 `display/window/size` 配置（靠 1152×648 默认值）。
8. `UiKit.font()` 用 `SystemFont` + Microsoft YaHei，非 Windows 导出（Android/Web）会掉字形，需内置字体文件兜底。

性能隐患（后期才爆，实测 125 只无压力）：
- 三件武器各自全表扫描敌人，无空间索引；子弹用线段判定（正确，防穿透）。
- Enemy/XpGem 全部自绘 `draw_circle`/`draw_arc`/`draw_colored_polygon`，无法跨节点合批；满预算 420 只约 1700 条指令。
- 无对象池，敌人与宝石靠 `new()` + `queue_free()` 高频分配。
- `_update_hud()` 每物理帧构造 3~4 个格式化字符串。

已确认做得对的地方（不要动）：`world` 用 PAUSABLE 隔离假暂停、武器走「每敌人独立冷却」、子弹线段判定、`Score.total` 与 `compute` 共用常量、`ScoreBoard` 的 JSON 归一化、信号全部带类型且 snake_case。

## 第六轮：修前三项（刷怪距离 / 敌人分离 / 闪白+InputMap）

### 1. 刷怪环改为按视野实算
- 删除 `SPAWN_MIN_DISTANCE` / `SPAWN_MAX_DISTANCE` 与「开局 6 秒近距离」特例。
- 新增 `_spawn_offset(angle)`：`extent = 视口尺寸 / (2 × Player.CAMERA_ZOOM) × SPAWN_MARGIN`，按椭圆采样再乘 `1.0 + randf() × SPAWN_RING_SPREAD`。
- `SPAWN_MARGIN = 1.06`，`SPAWN_RING_SPREAD = 0.3`。
- 验证：720 个角度扫一圈，最小椭圆比 **1.060**（>1 即在视野外），换分辨率/宽高比自适应。
- 为什么不能用写死常量：默认 1152×648 + zoom 1.35 → 世界半宽仅 426.7，原 340~430 有一大截在屏内。

### 2. 敌人分离
- 新增 `scripts/enemy_grid.gd`（`class_name EnemyGrid extends RefCounted`，约 50 行）：48px 均匀网格，`insert()` / `query(pos, out)`，`NONE` 空数组常量避免查空分配。
- `Game._physics_process` 里 `_cull_far_enemies()` → `_grid_rebuild()` → `_apply_separation()` → `_cull_far_gems()`。
  顺序关键：Game 是 World 的父节点，`_physics_process` 先于敌人执行，敌人才读得到本帧邻居。
- 分离分两层：`enemy.separation`（单位向量，权重 `SEPARATION_WEIGHT = 1.6`，在 `Enemy` 里 `(dir + sep×1.6).limit_length(1.0)`，所以挤住时自动减速）+ **位置修正**（按最深的一处重叠消掉 `SEPARATION_RELAX = 0.6 × radius`）。
- 只施加力不做位置修正时残留穿插约 60%（实测 157 对重叠不再下降），加修正后收敛到 3.7% 浅穿插。
- 验证（80 只怪压在玩家身上）：重叠对数 2825 → 40 帧 128 → 稳定 ~110，`severe`（重叠 >50%）0，平均最近邻 17.9（满距 20），簇半径稳定 97px，不抖动。
- 视觉确认：截图中每个红圈都独立可辨，右下 6 只汇聚时仍各自分离。
- **副作用**：贴身敌人数从"全部"降到内圈几只，难度会略降，需要重跑 bot 基准校准。

### 3. 闪白去 Tween + InputMap
- `Enemy` / `Player` 的 `_flash()` 改为 `_flash_t = FLASH_TIME`，新增 `_tick_flash(delta)` 用 `Color.WHITE.lerp(FLASH_COLOR, t)` 倒数插值。原因：高密度下每秒上千次受击会持续 `create_tween()` 分配，且同一敌人连续受击时多个 Tween 互抢 `modulate`。
- `Player._input_dir()` 改为 `Input.get_vector("move_left","move_right","move_up","move_down")`。
- `project.godot` 新增 `[input]` 段，4 个 action 各绑 WASD（`physical_keycode`）+ 方向键（`keycode` 4194319~4194322）。
- 简写 `Object(InputEventKey,"physical_keycode":65)` 能被 VariantParser 正常解析，godot 会补全其余属性。
- 验证：4 个 action 均 `has_action=true`、各 2 个事件。

## B 档手感三件套（震动 / 火花 / 红边）

### 屏幕震动 —— trauma 模型（`player.gd`）
- `camera` 从局部变量提为成员（`var camera: Camera2D`），震动直接改 `offset`。
- `add_trauma(a)` 累加上限 1.0；`_tick_shake()` 每物理帧 `trauma -= 1.7*delta`，位移 `= MAX * trauma²`。
- 位移用两个不同频率正弦叠加（1.7/2.9 与 2.3/3.7），**不要用 randf()**：60fps 下随机值是高频噪点，像画面撕裂。
- `SHAKE_MAX_OFFSET = 26`。**这个值实测校准过**：trauma=0.55（一次受击）峰值约 6.9px，在 853 宽的世界视野里"看得见但不晕"。初版写 10 只有 2.67px，等于没有。
- 触发源：受击 +0.55；普通击杀 +0.04（单次无感，靠连杀累积）；精英击杀 +0.25。
- **坑**：死亡瞬间会 `paused = true`，`_tick_shake` 停止、offset 永久冻结在偏移位置（画面歪掉）。死亡分支里必须手动 `_trauma = 0; camera.offset = 0`。

### 命中火花（新增 `scripts/hit_sparks.gd`）
- 单节点 + 5 组并行 `PackedArray`（pos/vel/col/age/life），`_draw` 一次画完所有线段。
- 不为每颗火花建节点：高密度下每秒数百次命中，节点分配与场景树遍历远贵于绘制；Godot 也不跨节点合批自绘命令。
- 末尾交换删除 O(1)；`MAX_PARTICLES = 260` 硬上限；粒子有阻尼 5.5 + 重力 340，尾巴长度跟速度走。
- `Enemy` 新增 `signal hit(at: Vector2, tint: Color)`，在 `take_damage` 里**先 emit hit 再判死**（致死那一击也要出火花）。
- `Game._on_enemy_hit()` 用 `HIT_SPARK_CHANCE = 0.5` 概率过滤 + 粒子上限双保险。
- 接入点：`_begin_run()` 里 `world.add_child(_sparks)`（`z_index = 2`，画在敌人之上）。

### 低血量红边（新增 `scripts/ui/damage_vignette.gdshader`）
- 全屏 `ColorRect` + `ShaderMaterial`，单 draw call。做成 shader 而不是多层 `draw_rect`：后者每帧上百条绘制命令。
- 方形距离 `max(|uv-0.5|)` 而不是圆形：圆形会让四角先亮，像"隧道视野"。
- **`mouse_filter` 必须 IGNORE**，否则全屏矩形吃掉升级卡的所有点击。
- 红边作为 `_root` 的第一个子节点 → 画在所有 HUD 之下，文字不会被染红；`_dim` 后添加，暂停时自然压住它。
- `max_alpha = 0.7`：给 1.0 时四边是实心红，会盖掉刚从屏外走进来的敌人——最危险时反而看不见威胁。
- HUD 侧 `set_danger(level)` 只收目标值，`_process` 里 `move_toward` 缓动 + 心跳脉动（1.5Hz → 濒死 3Hz），差值 < 0.004 不写 uniform。
- Game 侧 `_danger_level()`：血量 35% 以下线性映射到 0~1（`DANGER_HEALTH`）。

2. **gzip 后 Content-Length 没跟着改**
   第一版 serve.py 在 `copyfile` 里压了数据，但 `SimpleHTTPRequestHandler.send_head`
   早就按**原始大小**写了 Content-Length → 浏览器报 `ERR_CONTENT_LENGTH_MISMATCH`
   中止整个 wasm 加载，页面一直黑屏，canvas 都没创建。
   curl 不会报错（它宽容），**只有真浏览器会挂**。教训：动过 body 就必须自己写 header，
   干脆重写 do_GET 全文接管。顺便按 mtime 把压缩结果缓存到 `build/web/.gzcache/`。

3. **headless + swiftshader 渲染进程直接崩**
   `msedge --headless=new --disable-gpu --enable-unsafe-swiftshader` 截 WebGL 页面会
   "Abnormal renderer termination"。改用**非 headless 真实窗口 + CDP**（websocket-client），
   等 canvas.width>300 再等 12 秒才截图，稳定可复现。

### 其它踩坑
- GitHub Releases 下载被 schannel 吊销检查拦住（和之前 git 推不上去同因）：
  `curl --ssl-no-revoke` 即通。git 那边对应的是 `-c http.sslBackend=openssl -c http.sslVerify=false`。
- 导出模板整包 **1221MB**，速度 ~100KB/s 要两小时。只取 Web 模板：
  读 zip 尾部 EOCD → 中央目录 → 定位 `templates/web_nothreads_{release,debug}.zip`
  的 local header offset → Range 下载那 20MB → zlib 解压。
  模板放 `%APPDATA%/Godot/export_templates/4.7.2.stable/`。
- **Godot 导出不会自动创建输出目录**，`build/web` 不存在直接报"目标文件夹不存在"，
  而且要先 `mkdir` 再导出。
- CDP 截图的坐标必须按 canvas 的 `getBoundingClientRect()` 换算，按截图比例猜会点空
  （第一次点 (517,415) 落在按钮下方的空白，改成从截图里找黄色像素 bbox 才准）。
- 导出时临时脚本（`_check.gd` 等）会被打进 pck，验收后必须删干净再导出。
- Godot 会给根目录的 png 生成 `.import`，删 png 时要把 `.import` 一起删，否则进仓库。

## 23:20 P2-8 关卡结构（三章 + 无尽）

**设计**：`scripts/stage.gd` 是唯一数据源（名字/副标题/时长/关底 Boss/敌种权重/血量倍率/主题色）。
一局 = 三章 + 无尽循环；**打完 Boss 才进下一章**，章节时钟在 Boss 战期间冻结
（否则打得越久，下一章被压缩得越短，"击杀 Boss"反而变成惩罚）。

- 第一章 残响浅滩 70s（兵+冲锋）/ 第二章 锈蚀回廊 80s（+吐息）/ 第三章 深渊之喉 90s（+自爆）
- 每章前 15 秒只出普通小兵（`Stage.INTRO_TIME`）：新章第一印象必须是看得懂的局面
- 通关（打完第三章）→ 金色横幅 + 回满血 + 两张卡 + `Score.CLEAR_BONUS = 2500`，
  之后进入无尽轮次（`ENDLESS_HP_STEP = 1.3`，每轮 +10 秒）
- 甩掉了 `BOSS_FIRST_TIME / BOSS_INTERVAL / BOSS_NAMES / KIND_START_TIME / *_CHANCE`
  等一整套"按秒数解锁"的常量——现在这些问题的答案都在章表里

**改动了什么**：`game.gd` 的 `_check_boss/_spawn_boss/_on_boss_killed/_advance_stage/
_roll_kind/_create_enemy/_apply_stage_look/_update_hud`；HUD 加章节栏（标题+进度条，
关底变红）、章节横幅（进场/通关，暂停时冻结动画）；结算加"存活 · 章节名"与通关加分。

**关键决定**：
1. **横幅与发卡错开 1.5 秒**（`BANNER_READ_TIME` + `_card_delay`）。第一版换章即发卡，
   面板一压暗横幅就没了，玩家只看到一张卡、不知道自己进了第几章。
2. **HUD `_process` 在 `get_tree().paused` 时直接 return**，否则升级面板开着的时候
   横幅照样在背后走完，选完卡回来什么都没了。
3. 换章时 `_update_hud()` 立刻刷一次，不等 10Hz 节流——否则 Boss 出场后最多 0.1 秒
   才看到章节条变红。
4. `_roll_kind` 的特殊怪权重是"各自独立的概率"，剩下的一律小兵。
   不能给普通兵也写权重再归一化：每加一种特殊怪就会稀释普通兵占比，包围感跟着变弱。

**验证**：`dev/stage_check.gd` 55 项断言全通过（章节推进/关底换名/横幅/章节条归零/
延迟发卡/通关标记/无尽命名与血量递增/结算面板文本）。
`dev/shot.gd` 出 6 张图人工核对版式（桌面 + 960×540 触屏）。触屏上 Boss 血条下移到
y=104 会压住横幅，因此加了 `_layout_banner()` 把横幅在触屏上移到 36% 高度。

**平衡影响（必须记）**：章节奖励与"首只 Boss 提前到 70 秒"整体抬高了存活。
12 局（3 种子 × 4 策略，上限 420s）：站桩 74~81s、站桩放技能 136~152s、
走位 157~420s（3 局撞上限）。**结果是双峰分布**：要么在 150~200 秒崩，要么滚雪球到
上限——因为 `_roll_kind` 里 randf 的调用次数一变，固定种子的整条随机流就重排，
3 个种子分不清 20% 以内的差异。想真做平衡需要 8+ 种子，别再拿 3 局均值当结论。

**遗留**：无尽轮次目前只有血量在涨，玩家强度涨得更快（撞上限时还剩 110~223 血）。
真正的长线压力应该来自"同屏敌人数上限"（`_enemy_budget` 的 420/210 硬顶），
那是 P1-6 合批之后的活。

## 毒圈（BR 缩圈）设计定稿 · 尚未动代码

**为什么要做**：现在一局时长不确定，三条根因——① `_stage_time` 只在 `_boss == null` 时走，
打不动 Boss 就永远不换章也永远不死；② `_enemy_budget()` 封顶 420/210 + `_apply_separation`
把人墙推开，成型 build 能无限绕圈；③ 世界无限大，`_spawn_offset` 按视野外接椭圆刷怪，
直线跑就永远只遇到同速敌人。

**已拍板**：毒可致死 / Boss 战不暂停缩圈 / 目标中位数 5-7 分钟。

**缩圈表（半径用视野半径 V 的倍数，桌面 V≈545、手机≈408）**
1200(2.2V) 0-2:00 → 818(1.5V) 2:00 → 600(1.1V) 4:00 → 463(0.85V) 6:00
→ 338(0.62V) 8:00 → 245(0.45V) 8:45 → 0 到 11:30。
毒伤 0 / 1.0 / 1.6 / 2.5 / 4.0 / 6.0 / 10→18 %/秒。

**必须记住的实现约束**
- 毒伤走独立入口 `take_zone_damage()`：`take_damage()` 开头 `if _invuln > 0: return`，
  0.45 秒无敌会把 0.5 秒一跳的毒整个吞掉（被怪打时反而不掉毒血）。
- 圈心 = 旧圈心 + 随机方向 × (R旧−R新) × 0.55，保证新圈完整落在旧圈内。
- 敌人不吃毒（否则圈替玩家清场，白送击杀）；Boss 靠追玩家自然进圈。
- `_spawn_offset()` 结果要夹进 0.92R，否则 R < 视野半径时怪刷在毒里走不过来。
- 换算成 V 的倍数是为了手机（960×540）和桌面观感一致，写死像素手机圈会大 33%。

**风险**：现压力曲线 195 秒才拉满（GRACE 45 + RAMP 150），而圈 6:00 才进屏幕，
中位数很可能压不到 5-7 分钟。调整顺序：先只加圈跑 bot 基线（LIMIT 420→780），
不够就先提前收 2/收 3 各 30 秒，最后才动 GRACE/RAMP。
验收：0 局 >11:30、中位数 5-7 分钟、圈外死亡占比 15-35%、手机 ≥45 帧。

## 23:55 Boss 下一步优化（差异化招式 + 读招 + 掉落）

**问题**：三只 Boss 除了名字/血量/配色，招式轮换完全是同一套
（一阶段冲击波/召唤、二阶段弹幕/冲锋）。第三只和第一只打起来一模一样，
"关底"只剩下血厚这一个含义。

**改动（五件）**
1. **每只一套招式表**（`Enemy.BOSS_KIT_TABLES`，kit 由 `Stage.boss_kit()` 按**名字**查，
   不按章号——无尽轮次会循环复用这三只，玩家记的是"潮主会拍浪"）：
   - 潮主·潮汐 `冲击波→召唤→冲击波→召唤` / 二阶段 `巨浪→召唤→冲击波→召唤`
   - 蚀影·游影 `弹幕→瞬移→弹幕→冲击波` / 二阶段 `弹幕→瞬移→冲锋→弹幕`
   - 深潜者·深噬 `召唤→冲锋→弹幕→冲锋` / 二阶段 `追踪弹→冲锋→召唤→追踪弹`

   阶段切换时 `_boss_act` 归零 → 二阶段第一招固定是表头，可预测、可断言。
2. **新招式 3 个**：巨浪（r=250/20 伤/1.25s 前摇，冲击波判定改成带半径参数复用）；

   那等于一次躲不掉的接触伤害）；追踪弹（`EnemyShot.homing_turn`，2.2 rad/s ≈ 1.4 秒才能掉头）。
3. **出场定身 1.1 秒**（`boss_intro_t`）：不动不出招，配"关底 · 潮主 / 一句威胁提示"横幅。
   玩家要用这一秒确认"它来了、它叫什么、血条在哪"。
4. **掉落从 1 颗大宝石改成 8 颗散开**（8×6≈48 经验，与原来 45 基本等价）。
   这是整局唯一一处玩家会主动停下来捡的掉落，"打完炸出一地"就是胜利的实感。
5. **本体配色按 kit 区分**（青/橙/紫）。原来三只都是暗红，和普通小兵撞色，
   人群里只能靠"个头大"认 Boss。
